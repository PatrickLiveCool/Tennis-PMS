# 客户手机号纠错

用户于 2026-09-23 授权在会员详情补充有权限、有审计的手机号纠错。此切片纠正客户联系方式；客户身份仍由已有客户 ID 和经过核验的账号 / 渠道绑定决定。

## 业务契约

- 员工在会员详情点击「修改手机号」，核对当前号码、填写新的中国大陆 11 位手机号及修改原因。兼容粘贴 `+86` 形式，规范化保存为 `+86` 加 11 位号码；不支持清空号码。
- 写入要求当前员工拥有当前租户与所选场馆的 `manage_members` 权限。客户身份（包括同时有员工角色的用户在客户上下文中）、仅有 `book` 权限的员工不得操作；跨租户和无场馆权限不得操作。
- 请求携带读取时的 `expectedPhone`（可为空），在持有客户行锁后比较原值；号码已由他人修改时拒绝覆盖。相同新旧号码拒绝作为无效修改。同租户现存号码冲突必须明确报错，不能合并客户。
- 仅更新同一条客户记录的 phone；客户 ID、姓名、钱包本金 / 赠送及流水、订单、登录 subject、渠道绑定均保留。纠错不通过手机号迁移账号或身份；后续新客户也不继承旧号码客户的身份与资产。
- 业务更新、审计与命令回执在同一事务提交。审计记录操作者、客户 ID、场馆、原号码、新号码及原因；回执不额外返回原因。原号码、原因仅进入受控审计和提交草稿，不写普通运行日志。

## 接口及恢复

`POST /api/tennis/customers/:id/contact-corrections` 接受 `venueId`、`commandKey`、`expectedPhone`、`phone`、`reason`，返回 `{ customerId, customer }`。命令类型为 `customer.contact.correct`。

同一身份、租户、命令键和规范化请求重复提交返回原回执，只产生一次修改与审计；改用相同键提交其他内容拒绝。回执查询仍重验员工身份及当前 `manage_members` 场馆权限。

断网或未知响应保留原请求和命令键，冻结编辑，允许查询结果及按原内容重试；查无回执不代表未提交。刷新 / 重开同一会员可继续恢复。确认成功后读取最新会员资料，更新清单和详情。旧值冲突及号码重复等明确拒绝解除本次待确认状态，允许修改；权限拒绝不得被当成业务未提交来清除原未知请求。

## 验证范围

数据库与 HTTP 验证覆盖规范化、同租户号码冲突、跨租户 / 场馆 / 员工及客户身份权限、旧值并发防覆盖、重复命令和回执恢复、事务回滚、关联身份与资金记录不变。React DOM 验证入口权限、必填及格式、成功刷新、未知结果恢复与原内容重试。全量检查及桌面 / 手机浏览器走查由本次主任务合并验证；尚不表示生产部署或用户人工验收完成。
