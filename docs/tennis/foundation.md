# F0：环境隔离与分钟级库存基础

状态：实施规格，2026-09-18。本切片按库存 A 级验证；不是完整预约功能。

最新状态：F1 已追加 15 分钟约束，以及 [租户/场馆与受控库存](tenant-foundation.md)。原 001 迁移保持不变。下列 F0 内容保留原切片语义，具体当前结果以实施状态为准。

## 原 F0 行为（后续 F1 已补 15 分钟约束）

- 时间为带明确 UTC 偏移的 ISO 8601，精确到分钟；保存 `timestamptz`，区间为 `[startAt, endAt)`。拒绝空/逆序区间、无时区时间、非法日期、非整分钟。底层允许跨午夜，不等于业务已允许跨日售卖。
- 同一场地的有效占用不能重叠。BOOKING / COURSE / MAINTENANCE 使用同一约束；不同场地互不阻塞。released_at 非空表示已释放，历史记录保留。
- PostgreSQL `btree_gist` + `tstzrange` 部分排他约束保证并发防重；不依赖 Agent、预查询或进程内锁。单条 INSERT / UPDATE 的原子性保护占用；约束冲突映射为 INVENTORY_CONFLICT。
- 改期和释放需匹配 revision 且记录尚未释放。冲突时保留原时间与版本；旧版本操作返回 STALE_OCCUPANCY。
- 重复 id 返回 DUPLICATE_OCCUPANCY，不自动当作相同请求成功；完整命令幂等/回执在下一切片实现。
- 空闲时间函数从一个已给定的营业窗口减去占用，不自行决定营业时间、起订节点、价格或缓冲。
- 本切片只暴露内部 TypeScript 持久化函数，不对客户、Agent 或 Web 开放写 API。授权、审计、订单、占位到期和支付需要在后续命令服务中组合为事务；当前不能以占用记录代替已确认订单。

## 多片预订补充与当前实现缺口（2026-09-18）

用户确认：同一预订人可以在同一时段预订多片球场。单片资源占用是库存粒度，不是订单粒度；不能按预订人对时间去重，也不能限制一笔预订只能有一片球场。

现有表可保存不同球场的同时段占用，source_id 也未设置唯一限制；但 occupyCourt 仍是单片写入，循环调用不能保证整组原子性。因此 F0 的“不同球场可同时占用”测试不等于已完成多片预订。

下一库存/订单切片需要：一笔预订关联多条场地明细、整组可用性校验、原子占位以及一致的幂等/回执。建议同组任一片冲突时整体失败、原有占用保持不变；具体整单/部分改退规则待明确。校区与网球场馆已确认是同一层 Venue，其下为多片 Court；现有 venue_id 文本字段仍需补充正式场馆目录与引用约束。尚无订单、支付或客户权限实现，本次仅更正规格。

最低新增验收：同人同段三片成功；任一片被抢占时整组无部分残留；两个场地集合部分重叠的并发请求不超售；重复整组确认不增加占用；询问三片但只有两片时明确提示不足。

## 最新时间规格与不同时间明细（2026-09-18）

业务最小调度单位改为 15 分钟；起止对齐场馆当地时间的 00、15、30、45 分，时长为正的 15 分钟整数倍。常用预订时长为 1 小时；30 分钟和 45 分钟等时长可以表达，是否可售另由产品规则决定。原 F0 仅校验整分钟；F1 已追加 002 迁移及领域检查，19:07 等输入被拒绝，不静默取整，也未修改 001 checksum。

预订明细各自持有球场与起止时间，覆盖单片单时段、同段多片和不同时间组合。同片不连续明细之间的空档保持可用；同片明细互相重叠需拒绝，不因属于同一订单而豁免。订单汇总起止不能作为整段占用，整组事务要覆盖每条实际明细。

新增验收目标（尚未执行）：00/15/30/45 分边界及 1 小时常用输入正确；拒绝非 15 分钟边界且不静默取整；45 分钟课程可用；一单不同时间明细正确占用；同片间隙可由另一订单预订；明细内部冲突被拒绝；跨明细并发冲突时整组无部分残留。界面默认单片 1 小时，多片同段和不同时间明细按需添加。

## SaaS、多租户与租户配置补充（2026-09-18）

已确认我方为 SaaS 运营方，MVP 按多租户设计，计划先服务格林并用第二测试租户验证隔离，首期人工开通和收取软件服务费。租户可自行维护自己的场馆／球场、营业与维护状态、标准小时价及分时折扣。实体层级为平台 → Tenant → Venue（校区／场馆）→ Court。

原 F0 没有正式归属；F1 已追加 Tenant、Venue、成员权限、场馆范围、资产与占用复合外键以及事务内审计，库存函数必须传入可信员工身份与租户。公开认证、租户管理后台、价格/订单/资金仍待建设，不能把内部主体参数直接信任为客户登录身份。

新增验收目标：第二租户无法读取、修改或关联第一租户的资源和业务；工作人员仅在授权租户／场馆管理资产和价格；两个租户可有同名“1 号场”及不同价格；跨折扣边界分段计价、多明细汇总、旧订单价格不受新规则追溯修改；关闭球场不能静默覆盖已有预约。异步支付及到期任务必须验证原订单的租户和业务关联。单一时段折扣与重叠不得生效已确认：同一球场、同一使用时间最多命中一条，未命中用基础价；重叠配置提示解决后才可生效。会员已明确不额外打折，优惠券后置；舍入/分摊在实施规格固定，特殊日期按无重叠规则表达，不由 Agent 自行裁决。

## 环境隔离

本地 Compose 项目为 tennis-pms-local，端口 55439，独立卷。开发库 tennis_dev，测试库 tennis_test；迁移只执行 `packages/db/src/tennis/migrations/`，不执行住房迁移/种子。

bootstrap 数据库 URL 仅允许 `127.0.0.1:55439`、用户 tennis_dev 和按用途指定的库名，拒绝查询参数与 fragment，连接前检查。测试使用每次随机的场地/记录 ID，仅清理本次记录，不 DROP 数据库、不重置 schema、不终止其他会话。

本地数据库身份为开发管理员，只绑定回环地址；尚未设计生产 runtime/migrator 权限。API 4200、Web 4273 仅作预留，当前不启动网球页面或 API。

停用根 npm 中继承的住房运行、迁移/导入/重置测试与部署入口；旧生产 Compose 和四个发布/回滚/清理工作流移出活动位置。住房源码及其纯测试保留作复用依据；直接运行历史脚本仍可能访问住房默认地址，禁止按旧文档启动。

## 自动验证

1. 相邻时段可共存；部分重叠、包含、45 分钟课程、不同 UTC 偏移、跨午夜、空闲窗口裁剪。
2. 真 PostgreSQL 并发重叠请求最多一条成功；租场/课程/维护互斥，不同场地独立。
3. 改期失败保留原占用和版本；成功改期释放原时段；释放保留历史且允许再次占用；旧版本失败。
4. 直接 SQL 也不能写非整分钟、空区间、逆序区间和无穷时间。
5. 迁移重复执行无额外效果；已记录迁移 checksum 必须匹配。
6. 环境 URL 守卫在连接前拒绝住房库、开发库作测试库、外部地址和连接参数覆盖。
