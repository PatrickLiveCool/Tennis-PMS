# 持久充值目录与原单恢复

F11 补齐日常核对入口。会员余额页按当前客户和场馆查询线上充值付款单，支持全部、待付款/待核对、失败、已入账筛选及分页。记录来自数据库，不依赖当前设备的报价或付款草稿。钱包历史仍按同租户客户展示跨校区资金明细。

GET `/api/tennis/venues/:id/customers/:customerId/topups` 返回 `{items,nextCursor}`。可选 `status=PENDING|FAILED|SUCCEEDED`、`pageSize=1..100`（默认20）和上一页返回的 `cursor`。固定创建时间与编号排序，在 SQL 内比较精确时间；游标必须属于相同租户、场馆及客户。工作人员须有该场馆 `manage_members`，客户只看本人，每次翻页重新核权。

打开原充值单复用渠道查单与模拟验证入口。结果未知时查询原渠道操作，不用新建充值代替恢复；成功只计一次本金与赠送。查询目录不会创建商户、渠道操作或钱包记录。`topup.begin` 回执恢复时按 `topupId` 读取并打开原付款记录，不再只清除前端待处理提示。

022 仅增加查询索引，不改余额、赠送或充值生命周期。9项目录集成验证覆盖121条同刻、127条微秒记录、权限隔离、撤权、状态筛选及无资金副作用，HTTP与浏览器验证另记于实施状态。真实支付仍待外部商户联调。
