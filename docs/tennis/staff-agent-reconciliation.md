# 工作人员智能体收款核对

2026-09-22。依据本轮用户确认：智能体发起收款时建立业务与收款请求的关联，可信到账后自动核验；工作人员在企微独立收款后，可以通过工作人员智能体说明该款属于谁的订场或充值，由智能体查询真实流水并执行关联。

## 业务规则

- 收款发起和到账事实分开。带确定可信引用的流水继续通过既有 `ingestWecomCollection` 自动结算。本次新增的是工作人员智能体的查询和匹配工具，不把这条自动路径改成人工确认。
- 工作人员的明确指令是归属依据，金额、时间和业务名称用于找候选。查询始终返回候选列表，服务不按同额、昵称或聊天内容自行选中流水，也不创建到账事实。多个可能候选时 Runtime 补问交易号/时间等信息；明确且授权的指令不要求工作人员再进后台重复办理。
- 没有查到流水时返回空列表，Runtime 说明正在等待同步；只能在后续查到真实流水并持有有效授权后继续匹配。工具不伪造到账，也不持久保存一个绕过授权期限的自动认款任务。
- 对应业务必须有 PMS 付款记录。订场沿用已有订单、付款尝试和余额预留；充值沿用既有充值报价及付款记录。已有记录必须复用，不能为已收款业务再次向客人发送收款请求。
- 仅匹配该付款记录的外部应付金额：余额补差不含钱包部分，充值不含赠送。租户、原商户、支付通道、币种、金额、可信原引用逐项校验；同笔资金只能使用一次。
- 付款记录对应的占位已经失效时，沿用原资金异常处理，不恢复场地。多收和晚核对的返回可能为 `EXCEPTION`，不能回复“预约已确认”。退款仍走独立员工授权与退款渠道。

## 权限

新增可单独授予的员工权限 `reconcile_payments`（收款核对）。管理员沿用既有全权限；迁移不自动授权任何普通员工，客户身份即使对应主体兼有员工角色也不能调用。

租户未关联流水没有可靠场馆归属，此权限允许查询租户的待核对流水池。已关联流水不在候选中；带确定引用的待核对流水，仅在引用属于当前会话场馆且员工拥有对应业务权限时显示。该权限的可见范围需在员工授权时明确。

所有工具同时核验当前会话场馆的 `read` 和 `reconcile_payments`；查订单目标及关联订单另需 `book`，充值另需 `manage_members`。仅授予收款核对不会授予订场、扣余额、充值配置或退款权限。候选查询不返回客户电话、钱包或商户凭据。

接口身份、租户和场馆均取短期 Bearer 授权；不能由参数提供。结算事务重验成员、权限、场馆、授权期限、Gateway 绑定和人工接管代次。接管或撤权后旧智能体不能继续操作。

## 外部 Runtime 工具契约

基址 `/api/tennis/agent`，沿用 [Gateway](gateway.md) 发放的短期 Bearer token。以下查询拒绝额外身份或资金事实参数。

| 接口 | 输入与行为 |
| --- | --- |
| `GET /wecom/receipts` | 可选 `amountCents`（正整数分）、`paidFrom`/`paidTo`（带时区，左闭右开）、`q`（流水/交易编号）、`cursor`。返回 `{items,nextCursor}`，每页最多 50 笔未关联可信流水；不会自动选中 |
| `GET /wecom/payment-targets` | 必填 `sourceKind=ORDER\|TOPUP`；可选 `orderId`、`customerId`、`operationId`、`q`（客户名/订单编号/付款办理编号）、`cursor`。充值不接受 `orderId`。默认列未终态的付款记录，指定 `operationId` 可核对历史记录。返回 `{items,nextCursor}`，含可用于写入的 `operationId`，每页最多 50 条 |
| `POST /wecom/receipts/:id/link` | `{operationId,reason,commandKey}`。`reason` 记录工作人员明确指定的归属；不能只写“金额相同”。成功返回原收款记录，`LINKED` 为已入账，`EXCEPTION` 为实收已记录、需处理业务异常 |
| `GET /receipts/:commandKey` | 沿用原命令回执恢复，匹配命令类型为 `wecom.receipt.link`；结果仅包含 `wecomReceiptId` 及 `orderId/paymentId` 或 `topupId`，再读取对应业务核验当前状态 |

示例：工作人员说“刚收到张先生 120 元，记到今晚七点一号场”。Runtime 先用 `/booking-customers`、`/orders` 与订单详情确定业务，再查该订单的付款目标及近期 12000 分流水。不能确定唯一收款时补问。确定归属后以稳定的 `commandKey` 调用匹配接口，按工具返回及订单真实状态答复。

匹配、资金结算、钱包扣款或充值、审计、命令回执和智能体请求关联在同一数据库事务提交。相同键和参数可安全重试；同键改流水、目标或依据会拒绝并回滚。同一流水以不同键重试也不会重复入账。原会话请求详情保留业务结果，权限撤销后隐藏无权查看的资金命令。

## 验收范围

自动验证使用独立 `tennis_test` 数据库和合成可信流水，覆盖授权员工匹配、重复及并发、客户/越租户/越场馆拒绝、撤权及接管、不同业务权限、金额异常、迟到核对与命令恢复。

本次不修改外部智能体 Runtime，也不启动住房 worker。真实企微流水同步、Gateway 发起收款与官方流水编号的映射仍需各自真实适配和联调；API 测试通过不等于企微聊天已能执行。后台直连模型助手保留原只读职责，本工具属于企微连接的外部工作人员业务智能体。
