# 预订确认结果恢复（2026-09-23）

用户已授权修复：确认请求未到服务器、报价随后过期时，预订草稿被待核对命令永久挡住。

## 行为契约

- 待核对的预订确认显示“核对并恢复预订”。点击后先查原命令回执；查不到时，以保存的原报价、原保留条件和原 commandKey 重试确认，不采用用户后来修改的表单值，不签发新编号。
- 原报价仍有效时，这次操作可以完成原来确认过的预订；原单已经建立时，只恢复原单。服务端继续校验当前身份、场馆权限、库存及报价期限。
- 仅原请求返回 HTTP 409 / QUOTE_EXPIRED 时，视为服务端在同一事务内确认没有原订单且报价已过期，解除该条待核对记录。保留客户及所选时段，移除对应过期报价，允许重新核价。
- 只读查询没有回执、本机时间推测过期、断网、5xx、身份/权限失败、幂等参数冲突均不能解除待核对状态。退款、付款、充值不使用本次预订专用恢复规则。
- 成功恢复后打开原订单，仅清除仍指向原报价的预订草稿；不覆盖其他报价或后来修改的草稿。过期恢复同样只清除对应报价。
- 恢复期间防止重复点击，失败后仍可用原命令继续核对。保存的请求不完整时明确报错，不推测缺失参数。

## 验证范围

前端回归覆盖刷新后的原请求恢复、无回执且过期、响应丢失后的原单恢复、未过期原请求继续办理、权限/网络/其他业务错误保留、多个待核对命令互不清除、草稿保留及重复点击。沿用并复跑数据库预订用例，验证过期报价拒绝、已成交原单恢复和同键并发防重。浏览器分别走查桌面与手机尺寸；模拟故障及模拟订单与真实业务数据分开。
