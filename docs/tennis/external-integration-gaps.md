# 外部接入状态与剩余缺口

F8 在 F7 本地交付基础上补齐了以下四项 PMS 能力；真实渠道与 Runtime 仍未联调。源码、自动验证和浏览器演示各自记录，不把本文当成生产验收证明。

## F8 本地实现

| 能力 | 实现与契约 | 边界 |
| --- | --- | --- |
| 同租户替代场馆 | `GET /agent/available-venues`，核验完整时段与所需片数，复用确定性定价。见 [发现接口](agent-discovery.md) | 只读推荐、不锁场；新场馆需新会话和报价，旧 token 不扩大写权限 |
| Gateway 身份与入站 | 平台创建单租户凭据、租户管理员绑定已有客户/员工，入站去重、有限授权与撤销。见 [接入协议](gateway.md)、[管理界面](gateway-admin.md) | 渠道签名和真实身份由外部 Gateway 验证；无自动手机号合并或注册 |
| 业务事件 | 同事务记录业务事实，长期受控凭据可按随机游标轮询，权限过滤后分页。见 [业务事件](business-events.md) | 不自动发微信消息，不附完整客户档案；不是通用消息平台 |
| 未知请求恢复 | requestId 与命令回执在业务事务内持久关联，后台/ Gateway 只读核对，接管后旧写授权保持失效。见 [外部助手](external-agent.md) | 不自动重派 UNCERTAIN，不把自然语言回复当资金事实 |

自动验证覆盖见 [实现状态](implementation-status.md)。015–017 为追加迁移，原001–014校验保持。

## 仍可本地推进

### 5. 支付适配接口与真实渠道替换点

**规格要求：** 支付适配承担发起支付/退款、结果验证、主动查单与补偿；场地款和充值款直接进入各租户商户账户。

**当前缺口：** 付款/充值业务函数直接依赖 `LocalMockPaymentGateway`，模拟器提供签名及验签，尚无统一的发起、退款、查单接口或交给入口展示的付款动作契约。真实渠道接入仍需要代码，不是仅填写配置。

**最小技术建议，尚未实施：**

- 固化与具体微信产品无关的支付端口：创建付款、查询付款、创建退款、查询退款、验证通知；输入包含稳定业务请求标识及已受控解析的租户商户绑定。
- 明确发起成功、明确失败和结果未知的区别，以及查询/重试时保持原付款或退款标识的要求。
- 定义供入口消费的付款动作结果；具体渠道参数由适配器负责，模型不能编造二维码、支付链接或认定到账。
- 保留现有金额、原路退款、余额预留和防透支规则；模拟适配器用于契约验证。不得将 MOCK 事件包装成真实渠道事实。

**本地验收建议：** 模拟发起后丢响应、主动查到成功、同请求重试不重复发起、错误租户商户拒绝、退款保持原支付来源。真实 SDK 参数、商户证书和真实资金验证不在这些本地测试中冒充完成。

## 必须等待真实渠道或资料的验收

| 待具备条件 | 届时必须验证的结果 |
| --- | --- |
| 实际微信入口及有效账号 | 渠道签名/身份验证、真实客户与员工首绑、消息接收/回复、渠道侧去重与人工协作 |
| 外部 Runtime 地址及指定模型配置 | 实际协议互通、工具调用、用户确认、超时恢复、接管后停止旧操作；Runtime 仍由体外实现 |
| 各租户真实支付商户配置 | 场地款与充值款进入正确租户商户；真实发起/查单/回调验签/退款及渠道异常核对 |
| 可用托管环境与域名 | 外部回调可达、HTTPS、凭据保管、运行监控及部署后的完整联调 |
| 真实资产/价目/有效预约/会员期初资料 | 导入来源、金额与本金/赠送拆分、全部有效占用、余额及流水核对，最后进行业务人工验收 |

## 后续执行边界

支付端口和模拟契约可继续本地开发，不需要再次询问微信产品或 Runtime 选型。实际 SDK、渠道身份、商户证书、模型地址和生产部署随外部条件确定。客户自动绑定、跨租户余额共享、平台代收等均不在已确认范围内。
