## F9 支付适配本地实现

统一支付端口、不可变商户版本、同事务渠道意图、事务外投递/查单、可信观察恢复及平台/交易界面已经落地，详见[支付契约](payment-channel.md)。付款/充值/改期补款均只请求外部实收金额，退款固定原商户与原交易号。UNKNOWN 先查原单，只有退款已确认终态失败且员工授权后才建立新的渠道代次。

MOCK 使用独立持久渠道记录，支持模拟服务器重启、响应丢失、查单与回调并发；没有内存 Map 冒充持久化。真实微信适配器仍需开发与真实验证，不是填写商户号即可启用。WECHAT 配置页面仅预配置，当前不产生真实付款动作。

## F13 微信协议共用安全层

已实现产品共用的请求签名、响应验签及通知先验签后解密，参考微信支付官方 Go SDK 的固定版本协议。它只构造请求和核验原始报文，不进行网络请求、不生成可信资金事件、不启用 WECHAT provider。源码及接口边界见 [微信 API v3 安全层](wechatpay-v3-security.md)。

这项工作不依赖真实凭据，已自主推进；后续具体付款产品、网络 transport、商户凭据解析、原业务编号映射及资金事实校验仍需完成。没有将“已实现共用密码协议”写成“微信支付已接通”。

## F14 微信 HTTP 共用请求层

产品共用网络层已实现签名后的原样发送、TLS 验证选项、禁止重定向、覆盖全响应的 10 秒 deadline、流式限额、响应完整性核对及先验签后解析。真实回环 HTTP 演练使用合成密钥；没有访问微信或调用真实商户。源码与状态语义见 [微信共用请求层](wechatpay-v3-security.md)。

本层只返回已认证的未知业务 JSON 或 UNKNOWN，不将 404、网络错误、退款受理解释成资金终态。仍缺具体支付产品、按原商户版本解析凭据、业务编号映射和真实支付/退款联调；尚未注册 WECHAT provider。

## F15 退款原渠道金额

新退款请求已保存并校验原渠道交易总额，支持混合付款、部分退款、改期多笔实收及充值异常；历史请求/hash保持不变，仅授权失败重试的新代次补充缺失金额。真实退款创建所需 `amount.total` 已有可信来源，详见 [契约](payment-channel.md)。

它不替代支付产品选择、凭据解析、业务事件映射或商户联调。微信营销优惠与 `payer_total` 等返回金额语义尚需产品适配核对，不能将 MOCK 的金额一致性验证当成该部分已接通。
