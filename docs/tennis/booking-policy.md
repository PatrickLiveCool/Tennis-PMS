# 租户预订期限（F16）

补齐用户集中确认第6项“时长由租户配置”。原有5分钟报价、10分钟普通占位继续作为默认值，不再限定为固定值。校区/场馆最短可售时长、15分钟调度和常用1小时是另一组规则。

## 配置与权限

租户 ADMIN 在“场地设置 → 预订期限”设置全部场馆共用的 `quoteMinutes` 和 `paymentHoldMinutes`。GET/PATCH `/api/tennis/booking-policy` 使用当前可信会话租户，不接受调用方指定 tenantId；客户、普通员工（即使具有资产权限）、只读员工及无租户成员身份的平台运营员不能使用该配置入口。停用租户/成员照常拒绝。

两个字段接受1–1440整分钟，服务及数据库均校验。读取未配置租户返回默认5/10和revision=1，不隐式写入。保存必须匹配expectedRevision；使用与交易相同的租户锁，两个并发保存只有一个成功，另一个返回STALE_CONFIGURATION；配置前后值和操作者同事务审计。后台失败保留输入，可以“重新读取当前设置”核对数据库当前值。

## 生效时点和历史保护

- 新订场报价按当前quoteMinutes计算expiresAt，并快照paymentHoldMinutes。确认该报价时，从确认时间按快照计算holdUntil；重放确认不重新计时。新订单的普通占位、支付渠道期限及到期释放继续使用持久化的holdUntil。
- 新改期报价使用当前quoteMinutes及paymentHoldMinutes快照。已付款订单改期需要补款时，按快照生成待付期限，并维持原有“不晚于原/新场次开始”的限制。
- 未付款订单改期的报价有效期仍不晚于原holdUntil；确认不延长原订单期限。授权员工手工保留订单的until/reason继续按原明确输入办理。
- 配置修改不会追溯更新任何已有报价、订单或改期单。023追加booking_policies表及两个报价快照列；历史快照回填原先固定的10分钟，不修改expires_at/hold_until，不改旧迁移。
- 本配置适用于订场及改期。充值报价/支付、登录风控、Agent授权、回调签名时窗和渠道退避不属于锁场政策，继续使用各自既有契约。
