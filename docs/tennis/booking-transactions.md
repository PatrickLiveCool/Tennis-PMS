# 下一切片：报价、组合订单与支付事务

状态：2026-09-19 实施契约。报价/组合订单/未付款取消和到期，以及线下/模拟线上充值、余额/模拟混合付款/按明细退款已完成内部服务及自动验证；改期差额、公开 API 和网球 UI 待接入。以用户集中答复为依据；不改变已确认范围。

## 报价与预订

- 当前 `catalog.priceSelection` 只做确定性价格计算，不持久化正式报价，也不检查占用或锁场。正式报价需要验证可售与当前冲突，保存服务器产生的完整价格快照、租户/场馆/客户、创建主体、每条明细及有效期；有效期默认 5 分钟，按租户预订期限配置生成并持久化。
- 创建订单只接受服务器保存的报价 ID，不能信任客户端金额。客户只操作自己绑定的客户档案；员工按场馆与动作权限代办；接管需要以新主体重新预览，不能直接使用其他主体的确认凭据。
- 一单限同场馆，可含一片、同段多片、不同时间明细。每条明细独立关联 Court 和起止，同片不连续时段的空隙继续可售。内部明细重叠拒绝。
- 同组占位在一个事务中全部成功或全部回滚。报价有效不代表已有库存；确认时再验证营业可用性、球场状态、客户归属及实际冲突。数据库区间约束仍为最终防重保障。
- 有效报价的价格快照保持，不因刚更新小时价而追溯改价；需求改变或报价过期必须重报。营业关闭/维护和实际冲突仍能阻止确认，不能为兑现旧报价抢占他人资源。
- 普通待支付占位自成功创建开始计时，默认 10 分钟，使用报价时快照的租户配置。授权员工可保留未付款预约，但必须提供付款截止时间与原因，始终显示待收款，不能伪造付款成功。
- 订单状态与资金状态独立。查询、未付款占位、有效预订、取消/到期、服务完成有明确状态；付款成功才按对应规则转为已付，不用“人工确认”代替到账。
- 引入操作幂等回执：同主体、同租户、同操作键重复请求得到同一结果；同键不同意图拒绝。回执、订单、占用和审计同事务，失败无半单。重复确认同一已消费报价可恢复已生成订单，不新建订单。
- 订单管理的占用不能通过 F1 单条内部改期/释放绕过资金和订单规则。操作顺序统一为授权、场馆、订单/报价、球场/库存，避免配置与订单操作锁顺序相反。

## 余额、现金与退款

- 会员档案属于租户，可信登录/渠道主体绑定在授权边界完成；仅报出手机号不构成扣款授权。同租户各场馆使用同一客户余额，跨租户隔离。
- 充值本金与赠送以人民币分独立记账，支持批次、来源凭据和流水，不允许直接覆盖余额。线上支付到账校验与授权员工登记真实线下实收分别留痕。
- 按充值批次先后扣款，各批次按本金/赠送比例分配到分；取整余数有确定性规则，总额与两部分之和严格一致。退回时恢复原批次及原构成，不能把赠送变现。
- 允许余额＋微信补差。预留余额计入不可再次使用的额度；补差成功才完成整单，禁止并发透支。纯余额支付须将扣款、订单确认与库存原子提交。
- 到期或失败释放未消费的预留及场地。支付回调迟到、重复、金额/商户/订单不匹配须有确定性处理；不得重抢已释放后被他人占用的场地。需要退款或人工处理时产生明确待办，不能只写成功日志。
- 退款由授权工作人员确认金额与理由，按原付款来源返还；部分明细改退不能超过原明细及原资金来源累计可退金额。退款请求、发起中、已成功、失败待核实分别记录，回调/查单幂等。
- 改期失败保留原订单与占用。增加费用需要确认与补款流程；减少费用经人工确认后退款。不能先释放原场再尝试新场，也不能把退款处理中说成退款已完成。
- 充值实收、赠送、订单收款、储值消费和退款分别提供台账，避免把充值与之后的消费重复计入现金收入。

## 外部服务

- 未有支付商户号，本地模拟支付适配必须显式标识；不能通过同一未鉴权入口伪造真实到账。支付接口保留商户、币种、订单、金额与事件签名验证边界；真实联调在条件具备后执行。
- 智能体与 Runtime 在 PMS 外部。PMS 提供认证后的查询、预览/确认、状态/回执和接管接口以及事件；外部模型不得直接写数据库或决定资金事实。后台助手通过外部服务适配保留原入口与上下文。

## 主要验收

同人同段三片一次成功；任一片被抢占时整组无残留；不同时间明细空档可被另一单使用；重复确认不重单；到期与支付竞争只产生一致结果；两并发订单共用不足余额不能透支；混合支付失败恢复预留；原路部分退款金额与本金/赠送守恒；跨租户/客户/场馆访问拒绝；员工接管使旧智能体写入失效；结果未知能查询原操作。

## 未付款组合订单的部分调整（2026-09-19 补齐）

- 授权员工沿用 `book` 权限可按明细改期或取消 `HELD / UNPAID` 订单；客户不能调用员工调整入口。新建或延长人工保留仍须原 `hold_unpaid` 权限，本次调整不延长截止时间或改写原保留原因，因此不新增权限。
- 未付款改期沿用服务器预览、确认及改期历史。只对所选新时段重新报价，未改明细保留原价；预览有效期为租户配置的报价期限（默认 5 分钟）与原锁场截止时间的较早者。确认时校验原订单版本、原截止时间、可售规则及实际库存，在同一事务中替换选中占用并更新整单待付。冲突或到期失败均不先释放原场、不改付款记录；原锁场到期仍由既有到期流程处理。
- 未付款明细取消使用幂等命令和订单版本，保留未选明细及原锁场期限。剩余应付等于未取消明细的已确认价格合计；取消最后一条时转整单取消，沿用原整单取消的历史金额展示，不制造零元支付/退款。若保留时段合计为零，则沿用免费预约的 `CONFIRMED / NOT_REQUIRED` 语义，不继续等待付款。
- 被取消的未付款明细保留原价格供历史核对，但资金基数归零；后续对剩余时段付款、已付款改期及退款不能将其重新计入应付或可退款。未付款改期更新所选明细的资金基数，原报价与改期前后快照保留。
- 有 `PENDING` 付款（包括客户端结果未知但服务端已建付款）、非终态付款、已识别实收或实收异常时，拒绝未付款调整及部分取消。保留原占场、余额预留和支付事实，提示先核对原付款。确认与支付回调使用同一租户事务锁；不为了允许改单而取消、释放或覆盖原付款。
- API：既有 `POST /orders/:id/amendments` 与 `/amendments/:id/confirm` 支持未付款改期；新增 `POST /orders/:id/cancel-unpaid-lines` 仅供员工按明细取消。所有真实渠道条件与原付款/退款边界不变。
