# 房型与价格：人工验收用例与事项

适用分支：`codex/room-types-pricing-settings`。用户验收状态以[主人工验收计划的房型切片](./QinTopia-PMS-分步开发与人工验收计划.md#独立-a-级切片房型房间床位与价格管理2026-09-15)为准，当前待执行。工程测试与浏览器检查不能替代用户验收。

## 验收准备

- 从[设置首页](http://127.0.0.1:4243/settings)开始，点击「房型与价格」。另两个入口为「账号管理」「智能体与外部访问」，后者管理 API Key（Token）。
- 本地隔离验收环境：管理员 `admin`、员工 `operator`，密码均为 `demo-pass-2026`。只在 `127.0.0.1:4243` 操作；本轮不在生产环境增减库存或发布价格。
- 页面中的“今天”记为 D，以页面显示的门店营业日期为准；D+1 表示明天。退房日不算住宿晚数。
- 为避免影响已有验收数据，用自己的唯一后缀命名，例如「验收床位房-0915甲」和房号 `QA-0915A`。若房号已有占用，换新房号，不清空环境。
- 推荐顺序：A 组 → B1–B3 → 先建立 C1 的旧价订单 → B4 并核对 C1 锁价 → B5 → C2–C6。新房型未设价格前不能完成正常销售，这是预期行为。
- 每次保存需填写原因，经过“核对修改／核对并发布”以及最终确认才生效。可以在核对页返回修改或取消。

## A. 导航及房型、房间床位增减

| 编号 | 操作步骤 | 预期结果 |
|---|---|---|
| A1 设置导航 | 管理员点主导航「设置」，依次打开三个卡片。各子页互相切换，点击「返回设置」，再试浏览器前进、后退和刷新。手机也检查一次。 | 首页标题为「设置」，三个卡片均可点击；子页三个入口名称、顺序一致，当前入口高亮，始终能回到设置首页。房源内部三个标签只切换房源内容。 |
| A2 新增房型 | 新增「验收床位房-后缀」，选择公卫、按床位销售，默认 4 床；填写原因并核对确认。 | 列表出现新房型；显示按床销售、4 床／4 人；无关联房间，价格未设置。刷新仍存在，修改记录有新增事实。 |
| A3 新增及减少床位 | 给新房型新增一个房间（楼栋「验收」、唯一房号），4 床／4 人。再点该房间「调整」，改为 2 床并确认。 | 核对页显示修改前后结构；无占用时成功。设置及房态仅有 2 个有效可单卖床位，旧版本保留。不能出现原 4 床加新 2 床共 6 个可售床位。 |
| A4 重新分配房型 | 新建「验收整房-后缀」，按整房销售、2 张物理床、最多 2 人；把 A3 的空房调整为该房型，再调整回按床房型、2 床。 | 两次均须核对确认。整房模式只有整房销售入口，不因 2 张物理床而生成 2 个独立可售床位；改回按床模式恢复 2 个床位及整间销售组合。 |
| A5 停用和恢复 | 停用 A3 的空房，勾选「显示停用项」，再启用。之后停用其房型，再启用房型，并单独启用房间。 | 停用后房态不能销售该房和子床；历史可见。启用房型不会自动恢复所有房间，房间需按需启用；恢复后有效床位数量正确。 |
| A6 删除误建房型 | 另建一个未分配房间、未设价格的房型，再删除。尝试删除 A2 已使用的房型。 | 误建房型核对后可删除，操作历史保留；已使用的房型不能硬删除，应停用。不能把“删除”理解为连历史订单一起删除。 |

## B. 固定价格、试算与生效日期

统一使用 **1／7／14／30 晚 = 200／1000／1800／3000 元**。这里填写的是相应档位的总价，按床房型单位是每床，按整房房型单位是每房。

| 编号 | 操作步骤 | 预期结果 |
|---|---|---|
| B1 正式试算 | 给 A2 房型填写上述四档价格，生效日 D，先不确认发布。输入不同入住／退房日期，分别试算 1、6、7、13、14、29、30 晚。再跨月试算 30 晚。 | 金额符合下表；展示住宿晚数和档位。试算不创建订单、不占库存，也不提前改现行价。按默认 4 床整间试算 7 晚为 4000 元；实际 2 床房整间报价应为 2000 元。 |
| B2 输入、返回与取消 | 分别尝试空价、0、负数、超过两位小数的价、过去的生效日期、空修改原因。恢复合法值进入核对页，返回修改，最后取消一次。 | 无效内容不能发布；返回修改保留价格、生效日期和原因；取消后版本与现行价不变。 |
| B3 发布价格 | 重新填入上述四档价格、生效日 D，原因写“人工验收初始价格”。核对后确认，刷新页面。 | 四档现行价正确；历史有生效日、价格版本及操作记录；给实际 2 床房的单床报价 1 晚为 200 元、整间为 400 元。 |
| B4 明日调价及其他房型 | 先按 C1 建立一笔旧价订单，并记下另一个房型的四档价。给 A2 发布 D+1 起 220／1100／1900／3200 元。比较 D 与 D+1 入住的新报价。 | 今天现行价仍为旧价；价格安排中显示新版本待生效；今天新建的明日入住报价也用新价。另一个房型的现行价和已有排期不变。 |
| B5 同日更正与排期 | 给 A4 的整房房型先发布 D+2 起 300／1500／2500／4000 元，再把 A2 的 D+1 价格更正为 240／1200／2000／3400 元。 | A2 明日取最新更正价；旧同日版本仍可查，并标为被更正。A4 在 D+2 的价格仍为自己的排期，不被 A2 的更正覆盖。 |

| 晚数 | 选用档位 | 应付住宿金额（元） |
|---|---|---|
| 1 | 1 晚 | 200 |
| 6 | 1 晚 | 1200 |
| 7 | 7 晚 | 1000 |
| 13 | 7 晚 | 1857 |

金额沿用系统的时长分档规则：按所处档位折算整个连续住宿区间，最后住宿总额一次整元舍入。因此档位边界可能出现“多住一晚反而总价更低”；不代表每天逐日累加或节假日调价。

## C. 订单保护、历史与权限

| 编号 | 操作步骤 | 预期结果 |
|---|---|---|
| C1 已建订单锁价 | 完成 B3 后、B4 前，给 A2 的一个床位建立 D+1 入住、D+2 退房的普通预订，记录订单号及 200 元金额。完成 B4 后回到这笔订单，预览延长为 2 晚；再比较同房型的新订单报价。 | 原订单仍锁 200 元／晚的旧政策，2 晚预览为 400 元；新报价按入住日使用新政策。不能自动把旧订单改成新价。普通订单改期、续住、缩短和换房均沿用旧政策；原政策没有新房型价格时明确拒绝，不偷偷混用新价。 |
| C2 占用拦截 | 保留 C1 的未来预订，尝试减少该房床数、重新分配房型、停用房间或房型。也可先办理入住后再试停用。处理订单后再调整。 | 有未来预订或在住时阻止变更，不静默取消订单；处理订单后可继续。维修和权益占用同样不能被结构调整绕过。 |
| C3 历史追溯 | C1 订单通过正常流程取消／退房后，给原房间重新分配房型，再打开旧订单详情和设置修改记录。 | 旧订单仍能读取成交时的房间床位和价格依据；记录包含操作人、时间、原因及前后内容。新房型不应改写旧订单含义。 |
| C4 员工权限 | 退出管理员，用 operator 登录。打开设置首页，再直接输入房型设置地址。 | 员工可访问自己的账号页面，不能修改房型、库存和价格；管理员专属入口按权限显示。不可为了让所有角色看到一样的卡片而放开管理权限。 |
| C5 并发和结果恢复 | 两个管理员页面同时打开同一房型的编辑预览。B 页先确认名称修改，A 页再确认旧预览；刷新并看历史。正常确认后刷新一次，核对没有重复记录。 | A 页旧预览被拒绝并要求刷新，不能覆盖 B 的修改；一次成功操作只产生一条变更。如果出现结果未知，先用系统恢复／查询结果入口核对，不重新创建相同操作。 |
| C6 会员房源保护 | 使用已有未到期、限定房型的会员合同，尝试停用其房型或最后一间适用房源。若当前环境没有满足条件的合同，记录为“未执行，缺少样例”，不能记为通过。 | 明确阻断并提示先安排会员权益；不删除合同、不自动改变权益、不允许无定义的履约损失。 |

## 验收事项与反馈格式

1. **顺序例外：C1 的旧价订单必须在 B4 涨价前建立。** 建好后再执行 B4、C1 锁价核对、B5。同一用例重做时重新建立独立样例，避免把后来创建的订单当作“旧价订单”。
2. 新价格根据入住日判断，不根据操作当天判断；试算使用表单里待发布价格，不一定是所选入住日的线上现行价。发布前应核对房型、销售单位、生效日、四档总价和原因。
3. 按床房型的“默认床数”是模板，实际房间可有不同床数。默认整间试算使用模板床数，真实房间整租以该房物理床数为准。不得把实体床数、可单卖床位数和可住人数混成一个概念。
4. 已使用房间调整结构会保留历史身份并产生新版本；恢复后不能误认为旧版本被重新用于另一实体。停用房型后恢复房型，不等于自动恢复全部房间。
5. 记录通过／失败／未执行，不把未执行当通过。失败请提供用例编号、房型／房号／订单号、操作、生效日期、预期和实际结果；有报错时附界面关联编号或截图。
6. 本轮人工验收不包括生产发布、真实 API Key 签发、真实收退款或恢复备份演练。账号与外部访问在 A1 中只需验证入口及页面到达。

可直接反馈：“A1–A6 通过；B1–B5 通过；C1–C5 通过；C6 未执行（无会员样例）”，或逐项写问题。主计划在收到实际反馈后再更新状态。
